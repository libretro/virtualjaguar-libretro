Enhancements

Beyond faithful emulation: features the original hardware never had, built so that the stock pipeline stays bit-identical when they're off — and measured, not just screenshotted, when they're on.

True-color rendering in review — PR #341

The Jaguar's blitter computes Gouraud-shaded intensity with 16 fraction bits of precision — and then throws them away when it writes a 16-bit CRY pixel. The true-color shadow framebuffer keeps them: with virtualjaguar_true_color = enabled, shaded pixels are also stored at full precision (CRY chroma × 24-bit intensity) in a shadow buffer, and the scanline renderer substitutes them at output time. Game-visible RAM stays bit-identical — the game cannot tell the difference; your eyes can.

The numbers (from the PR's validation record): unique on-screen colors 304 → 450 (peak frame 423 → 702); both blitter engines (fast and accurate) agree exactly; with the option off, 600 frames across three cartridge titles hash bit-identical to develop. CRY 16bpp only, default off, ~8 MB allocated only when enabled. Status: in review — PR #341, design doc committed with the PR.

Overclocking that doesn't break the game

Two independent clock-scale options: the 68000 (virtualjaguar_m68k_clock_scale, 0.5×–3×) and the RISC GPU/DSP pair (virtualjaguar_risc_clock_scale, 0.5×–2×) — for framerate-limited titles that leave silicon on the table.

The part that usually goes wrong elsewhere is pacing: naive overclocks speed up the game, not just the processor. Here, bus and DRAM latencies are charged in wall time under any clock scale — the cycle-domain contract — so the timing model isn't distorted, defaults are bit-identical to previous behavior, and audio pitch is proven unchanged at every scale by CI rows that run at non-1× scales.

Sources: v3.1.0 notes (#314, #316) · cycle-domain contract #318 via PR #337 (merged).

CD read-speed control

virtualjaguar_cd_read_speed: 1× (hardware-faithful) through 2×/4×/8× up to instant, trimming load screens on the HLE CD path. Implemented with streaming reads so accelerated transfers can't overwrite in-flight game code — the failure mode that instant reads used to cause is documented, fixed, and regression-tested.

Sources: docs/cd-read-speed.md · v3.0.0 notes.

Crash watchdog

A runtime watchdog (virtualjaguar_crash_detect, on by default) checks once per frame for known failure signatures — GPU/DSP program counter escaping valid memory, a processor wedged on one PC, a frozen framebuffer, a stalled CD seek — and writes the diagnosis into the frontend log at the moment of failure. A user's log line replaces an hour of triage: it names the subsystem that broke.

Source: src/core/crash_detect.c (signature list and thresholds in the header comment).

Roadmap: internal hi-res upscaling in design

The true-color shadow framebuffer above is deliberately the 1× prototype of a larger architecture: rendering the Jaguar's output above native resolution inside the core. That work — along with the rest of the enhancement suite — is tracked as epic #338. It is in design; no dates, no promises beyond what's in the issue.
