Why this core

Not a comparison chart — a list of what you get here, each line backed by a commit, test, or merged PR in this repository. We make no claims about other emulators' internals; where we state something comparative, it's labeled as our current knowledge and corrections are welcome in Discussions.

What you get

Every platform RetroArch runs on

One codebase, 16 CI-built targets on every release: Linux (x86_64, aarch64, i686), macOS (Apple Silicon + Intel), Windows (x64 + x86), Android (all four ABIs), iOS, tvOS, and WebAssembly. Handhelds and consoles that run RetroArch get the core through the libretro buildbot ecosystem.

release.yml build matrix

RetroAchievements

Memory maps and achievement support are exposed and asserted by a test — including a CI harness that checks the rcheevos Atari Jaguar console mapping resolves against this core's RAM.

test_memory_map.c · test_rcheevos_e2e.sh

Run-ahead, rewind, netplay-grade determinism

The core declares deterministic savestates to the frontend — the level run-ahead and netplay depend on — and backs it with a harness that reproduces RetroArch's rollback loop and demands byte-identical replay. Rewind and instant savestates come with the same machinery.

PR #327 · test_runahead_determinism.c · savestate-compat.md

Shaders and frontend features for free

As a libretro core, everything the frontend provides applies: CRT and upscaling shaders, per-game overrides, input remapping, fast-forward, screenshots, streaming. The core's job is clean XRGB8888 video and 48 kHz audio; RetroArch does the rest.

libretro.c (API implementation)

Documented where you'd expect it

The core has a page in the official libretro documentation: supported extensions, the core options reference, controller tables and frontend feature support. No BIOS or system files are required to play — the boot ROM and both Jaguar CD BIOSes ship inside the core.

docs.libretro.com — Virtual Jaguar · core options · README: BIOS

Savestates that never expire

Every savestate format any released version of this core ever wrote still loads — exactly, not best-effort. The loader was audited against all four released layouts after older states were found to silently mis-parse.

savestate-compat.md · v3.1.0 notes (#268, #301)

Jaguar CD, JagLink, GameDrive, Memory Track

The peripherals, not just the console: CD (HLE and real-BIOS paths), link-port networking over TCP, GameDrive bank switching, Memory Track saves. Details and evidence on the front page.

Hardware-referenced accuracy work

Emulation decisions are checked against the Jaguar Technical Reference Manual, and an acid test suite of hardware-behavior assertions gates CI. When a "fix" can't be grounded in the manual or a measurement, it doesn't ship.

Fully open source

GPLv3. Every fix on this site links to its PR; the test harnesses that verified it are in the repo; the docs that record the failures are committed alongside the ones that record the wins.

One comparative claim

We know of no other Atari Jaguar emulator offering a true-color rendering mode or an internal-resolution upscaling track like the one described on the enhancements page (true-color has merged and ships in nightlies, hi-res is in design — labeled as such there). If we're wrong, we'd genuinely like to know: tell us in Discussions and this page gets corrected.

Found something broken?

Compatibility reports belong in GitHub Discussions (or Issues for confirmed bugs). Attach your frontend log — the built-in crash watchdog writes the failure signature at the moment of the crash, which usually identifies the subsystem without a save state or a reproduction recording.
